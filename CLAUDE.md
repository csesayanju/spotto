# Spotto – project context for Claude Code

Spotto is a private, non-commercial, mobile-first online version of a "spot the
match" card game (every pair of cards shares exactly one symbol), built by Sayan
to play with friends. Do not use the original game's name, artwork or branding.
Copyright line in the app: "© <year> Sayan".

## Hard constraints

- **Everything stays free.** Firebase Spark plan only (no Blaze, so no Cloud
  Functions). GitHub Actions for CI/CD. No paid services (no Play Store / App Store).
- Never commit `.env`, service account JSON, or any token. Firebase web config
  lives in `.env` locally and in GitHub Variables for CI.
- **Sayan keeps no local copy.** Work in a throwaway clone and push branches; CI
  builds, tests and deploys. Sayan uses **PowerShell** (not CMD), so give
  PowerShell commands.
- Claude's auto mode blocks some GitHub writes (creating PRs, merging, tags,
  repo variables/secrets). Give Sayan the `gh` command to run instead.
- Never type secrets (service account key, tokens) into anything; Sayan does that.

## Stack

- React 19 + TypeScript 7 + Vite 8 (Rolldown), mobile-first portrait web app
- Firebase Realtime Database (asia-southeast1) + Anonymous Auth, firebase 13
- Firebase Hosting → https://spotto-dobble.web.app (project `spotto-dobble`)
- Capacitor 8 Android app (`android/` committed; Java 21, SDK 36); APK attached
  to each GitHub Release, signed with the shared `android/app/spotto-friends.keystore`
- Installable web app (PWA): `public/manifest.webmanifest`, `public/sw.js`
- Vitest 5; database rules tested with `@firebase/rules-unit-testing` + emulator
- Repo: https://github.com/csesayanju/spotto

## Architecture

- `src/shared/` – deck (projective plane, order 7 → 57 cards × 8 symbols),
  types, config, seeded random
- `src/engine/` – pure, tested rules. `ModeRules` in `rules.ts` (setup,
  resolveTap, isOver, winsWith). Modes: `tower`, `well`, `gift`, `potato`.
  Also `match.ts` (best-of), `roster.ts` (spectator promotion), `daily.ts`
  (daily seed, ranking, streaks), `host.ts`.
- `src/net/` – Firebase. `rooms.ts` (create/join/leave, spectators, kick,
  invites, resetToLobby), `game.ts` (startGame, tap arbiter = transaction on
  the whole room, finishMeta tallies room/match wins, endIfExpired for timed
  games), `presence.ts` (role-aware onDisconnect), `status.ts` (server clock,
  online, open/closed switch), `daily.ts` (daily leaderboard).
- `src/ui/` – screens (Home, Lobby, Game, Watch, Results, Practice, Daily,
  StatsScreen, Closed), components, sound (Web Audio), prefs (big symbols),
  theme (symbol themes via context), stats (device-only), install (PWA).
- DB shape: `rooms/{code}/{meta, players/{uid}, spectators/{uid}, game}`,
  `daily/{YYYY-MM-DD}/{uid}`, `config/open`.

## Database rules (`database.rules.json`)

- **CI deploys them on release; never edit rules in the console.**
- Realtime Database rules can't count children (`numChildren` doesn't exist),
  so the 8-player cap is enforced by the app.
- Rules tests live in `tests-rules/` and run in CI (`Database rules` job) via
  the emulator; `npm test` skips them. Add a test with every rules change.
- PR previews share the live database **and live rules**: features that need
  new rules (e.g. spectators, daily) only work after the release deploys them.
- Owner's off switch: set `config/open` to `false` in the Firebase console
  (data, not rules). The app can't write it.
- Analytics: `analytics/{day}/{id}` append-only anonymous events (fixed field
  list, no IPs); readable only by `admins/{uid} = true` (set in the console).
  Dev page at `?dev`. Google Analytics is optional via `VITE_FIREBASE_MEASUREMENT_ID`.

## CI/CD (.github/workflows)

- `ci.yml` (PRs and pushes to main): typecheck/test/build, Android APK build,
  database rules tests, and a 7-day Firebase preview channel for PRs.
- `release.yml` (tags `v*`): checks tag == package.json version, deploys
  hosting + database rules (firebase-tools@15.31.0), builds the APK and
  attaches it to a GitHub Release.
- Secret `FIREBASE_SERVICE_ACCOUNT`; variables `VITE_FIREBASE_API_KEY`,
  `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_DATABASE_URL`,
  `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`.

## Release process

Branch `release/x.y.z` from `origin/main` → bump `package.json` version and
`CHANGELOG.md` → push → Sayan opens the PR → check CI and the preview →
Sayan merges and tags:

```powershell
gh pr merge <n> --repo csesayanju/spotto --merge
$sha = gh pr view <n> --repo csesayanju/spotto --json mergeCommit --jq .mergeCommit.oid; gh api repos/csesayanju/spotto/git/refs -f ref=refs/tags/vX.Y.Z -f sha=$sha
```
